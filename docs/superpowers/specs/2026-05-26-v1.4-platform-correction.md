# v1.4 — Platform Correction (Postmortem do Grab)

> **Atualização v1.5 (mesmo dia):** depois de testar v1.4 no device, descobrimos que **pinch polegar+médio (Escape) é interceptado pelo sistema como navegação 'back' e nunca chega ao Web App.** O cycle de modo e toggle de física dependiam dele e ficaram mortos. v1.5 move tudo pra pinch indicador (single = reset, double = cycle) e tira o toggle de física do vocabulário de gestos (vira URL param `?physics=frozen`). ## TL;DR

v1.3 implementou grab contínuo do pulso, mas no device falhou por duas razões de plataforma que eu (Claude) não verifiquei direito antes de codar:

1. **`DeviceOrientation` reflete a cabeça, não o pulso.** O comentário antigo do `imu.js` claimava wrist — estava errado. No device, mexer o pulso não muda nada; só virar a cabeça muda. O grab "seguindo a mão" seguia o olhar.
2. **Pinch + manter fechado + mexer o pulso = gesto de volume do sistema.** Single pinch isolado vira `Enter` pro Web App, mas se você mantém a pinça enquanto move o pulso, a Meta intercepta como pinch+twist e mexe o volume — exatamente o que o usuário descreveu.

Consequência: o desenho do grab é inconstruível no Web App. O caminho pra ter wrist contínuo é a [Wearables Device Access Toolkit nativa](https://developers.meta.com/blog/build-for-display-glasses/) (Swift/Kotlin), que é outro build path — fica como decisão separada se vale a pena.

## O que foi corrigido em v1.4

- **`main.js`:** removida toda integração com `grab.js`. Voltou pro padrão discreto:
  - rotate mode: swipes ←→↑↓ aplicam impulso angular (yaw/pitch). Damping decelera.
  - scale mode: ↑↓ aplicam impulso de escala, ←→ resetam zoom.
  - Pinch single (Enter) = reset total (rotação + zoom + velocidade).
  - Pinch médio single (Escape) = cicla modo.
  - Pinch médio double (Escape Escape <400ms) = toggle física `damped` ⇄ `frozen`.
- **`grab.js` + `tests/grab.test.js` deletados.** Não há caminho viável pra revivê-los no Web App.
- **`imu.js` mantido** com comentário corrigido — não está sendo usado em v1.4, mas o módulo é reutilizável se um dia alguém quiser modo "look-to-aim" baseado em cabeça (uso intencional, não bias acidental).
- **`multitap.js` mantido** — é uma limpeza genuína, melhor que o `lastEnter/lastBack` ad-hoc do v1.2.
- **Sem IMU bias em rotate.** v1.2 misturava `imu.step()` em rotate mode pra dar "drift" de inclinação — no device isso significava cubo virando junto com a cabeça. Removido.

## O que ficou da v1.3 (decisões boas que sobreviveram)

- **physicsMode toggle** (damped/frozen via double Escape): mantido. Útil de verdade.
- **Versão bump + cache bust em HTML**: mantido (1.3 → 1.4).

## O que NÃO tem no Web App (limitação confirmada)

- ❌ Posição XYZ do pulso
- ❌ Orientação contínua do pulso (alpha/beta/gamma)
- ❌ Sinal EMG bruto
- ❌ Twist como evento (reservado pelo sistema)
- ❌ Keyup confiável pra pinças (não há "soltar")

Disponível:
- ✅ Gestos discretos: pinch+index, pinch+middle, swipe 4 direções
- ✅ `DeviceOrientation` da cabeça (uso intencional só — não como bias passivo)
- ✅ `Geolocation` do celular pareado
- ✅ `localStorage`

## Caminho futuro pra controle contínuo (se importante)

Construir o app nativo via [Wearables Device Access Toolkit](https://developers.meta.com/blog/build-for-display-glasses/):

- Swift (iOS) ou Kotlin (Android) — não JS.
- Roda como app no celular pareado, espelha pro display.
- Documentação Meta cita "Neural Band gesture controls" mas não confirma se expõe IMU bruto da pulseira. Risco: pode ser também só gestos discretos.

Antes de embarcar nesse rewrite, vale spike de 1-2h com o starter SDK pra confirmar se o IMU/EMG raw é exposto ao app nativo.

## v1.5 update — pinch médio também não chega

**Descoberto:** ao testar v1.4 no device, o usuário relatou que o gesto de pinch polegar+médio simplesmente não tem efeito nenhum. Isso significava que **nenhum** dos controles montados em `Escape` (cycle de modo + toggle de física) estava funcionando.

**Causa:** Meta Display intercepta pinch polegar+médio como navegação **'back' do sistema** (fechar tela atual / voltar) **antes** de despachar um KeyboardEvent. Os docs falam que vira `Escape`, mas na prática só o sistema vê o gesto.

**Mudanças em v1.5:**

- Single Enter (pinch indicador, rápido) → **reset all** (após 280ms pra disambiguar do double-tap)
- Double Enter → **cicla modo** (rotate ⇄ scale) — instantâneo no segundo tap
- `MULTITAP_WINDOW_MS` reduzido de 400ms pra 280ms — sensação mais snappy agora que o reset depende dele.
- `onBack` permanece wired (caso firmware futuro entregue Escape), mas não faz nada.
- **Toggle de física via gesto: removido.** Default `damped`. Override via URL param `?physics=frozen`.

### Gestos que NÃO funcionam no Web App

- ❌ Pinch polegar+médio (single ou double) — sistema absorve como back
- ❌ Pinch+twist do pulso — sistema absorve como volume
- ❌ Long press — não há keyup; long press emite o mesmo single keydown

### Lição número 2

Cada vez que um spec depende de uma tecla específica chegar, validar **uma vez** no device antes de cimentar o desenho. O spec de v1.4 dizia "Single Escape cycles mode" como fato, mas era assumption não validada. 5 minutos de spike teriam economizado um round-trip.
